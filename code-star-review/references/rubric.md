# 评分细则（rubric）

配套 `SKILL.md` 使用。SKILL.md 给判定顺序和总表，本文件给每一档的可操作锚点。

## 1. 判定顺序（不可调换）

```
① 确认评的是哪段代码（diff / 文件 / 函数）
② 跑 Gate → 得到星级上限
③ 五维各打 0-5，每维写证据
④ 加权 → 原始星级
⑤ min(原始星级, Gate 上限) = 最终星级
⑥ 输出：结论 + 证据 + 最小改进项
```

先 Gate 后五维，是为了防"平均分掩盖致命伤"。例如：功能全对、代码漂亮，但把 API Key 写进源码，仍是 1 星。

---

## 2. 五维锚点

### 2.1 需求达成（35%）

| 分 | 锚点 |
| --- | --- |
| 5 | 所有显式验收点 + 隐含约束（权限、兼容性、性能、国际化、向后兼容）全部满足；没有顺手加需求外的功能；改动范围恰好覆盖需求 |
| 4 | 显式需求全部满足，隐含约束基本覆盖（遗漏 1 项非关键约束） |
| 3 | 主需求可用，缺 1 个次要功能或某个使用场景；或有一处过度设计 |
| 2 | 缺主要子功能；实现方式偏离需求（如要求异步却做成阻塞） |
| 1 | 方向错误，只完成了名字/接口，行为与需求无关 |
| 0 | 未实现任何需求 |

**判定要点**
- 需求以用户本轮的原话和已有接口契约为准，不以"我觉得应该这样"为准。
- "顺手重构了无关文件"不扣需求分，但扣可维护分（改动非最小）。
- 需求本身矛盾时，按用户最后一句话为准，并在评分卡注明假设。

### 2.2 正确性与健壮性（25%）

| 分 | 锚点 |
| --- | --- |
| 5 | 正常路径、异常路径、边界（空/超长/超大/并发/超时/重复提交/顺序错乱）均有处理；失败可恢复、无脏数据、无资源泄漏 |
| 4 | 正常路径与常见异常正确；极端边界未覆盖，但失败是"报错退出"而非"写坏数据" |
| 3 | happy path 正确；异常被吞、错误码乱用、无输入校验，但不会静默损坏数据 |
| 2 | 存在逻辑错误：特定输入结果错、失败后留下半成品数据、重试导致重复扣款/重复写入 |
| 1 | 主流程即错，或依赖不存在的函数/字段 |
| 0 | 语法错误、必然崩溃、进入死循环 |

**判定要点**
- 判断"错"要看行为，不看写法。`try/except: pass` 是 3 分问题，不是 0 分。
- 并发问题只有在共享可变状态、无锁、无幂等时才计；单进程脚本不套用。
- 环境无法运行时，按静态分析给分，并在证据中写 `未验证（无法运行）`，验证维度 ≤2。

### 2.3 安全与副作用（15%）

| 分 | 锚点 |
| --- | --- |
| 5 | 输入校验与参数化查询；鉴权与最小权限；密钥/令牌走环境变量或密钥管理；无危险默认值；有超时、限流、审计；操作可回滚 |
| 4 | 无已知漏洞；个别防御性检查缺失（如未限制上传类型），但当前上下文风险低 |
| 3 | 低危：日志打印敏感字段、错误信息暴露堆栈、无限流、Cookie 缺 SameSite |
| 2 | 中危：越权（只校验登录不校验归属）、XSS、路径穿越、明文存密码/令牌、SSRF |
| 1 | 高危：SQL/命令/模板注入、任意文件读写、硬编码生产密钥、关闭 TLS 校验、绕过鉴权 |
| 0 | 直接造成破坏：删库、批量外泄、后门、勒索/挖矿代码 |

**判定要点**
- 密钥出现在代码、注释、测试夹具、日志里，都算硬编码。
- "内网环境所以不用鉴权"不是免责理由，最多到 3 分。
- 只写不读的危险操作（如 `rm -rf` 拼用户输入）按可利用性判定，不按是否真的执行过。

### 2.4 可维护性（15%）

| 分 | 锚点 |
| --- | --- |
| 5 | 命名达意；函数职责单一（<50 行、参数 ≤4）；无重复逻辑；贴合项目分层与依赖方向；无死代码/调试输出；diff 最小 |
| 4 | 结构清晰；少量重复或命名一般；有 1-2 处可读性瑕疵，不影响修改 |
| 3 | 能读懂但技术债明显：超长函数、魔法数、复制粘贴、层级穿透、注释与代码不符 |
| 2 | 难读难改：隐式全局状态、深层嵌套、职责混乱、强耦合 |
| 1 | 不可维护：单文件千行、无结构、命名 a/b/tmp |
| 0 | —（可维护性不单独判 0，由 Gate 处理） |

**判定要点**
- 与项目现有风格不一致要扣分，但"我不喜欢这个风格"不扣分；以仓库内同类文件为准。
- 生成式重复代码（复制 5 遍相似逻辑）按重复度扣，不按行数扣。

### 2.5 验证充分性（10%）

| 分 | 锚点 |
| --- | --- |
| 5 | 有自动化测试且覆盖关键分支与至少一个异常分支；或提供真实命令+真实输出+自检清单，结果与代码一致 |
| 4 | 手动跑通主流程 + 1 个关键异常，给出可复现命令与结果 |
| 3 | 只验证 happy path，或只说"应该可以运行"但没有输出 |
| 2 | 无任何验证，纯静态推断；或环境不具备且未说明 |
| 1 | 声称验证过，但证据缺失/与代码矛盾（如测试文件是空的） |
| 0 | 伪造结果：编造测试通过、编造日志、PS 截图 |

**判定要点**
- "我检查过了"不算证据；命令、输出、退出码才算。
- 有测试但测试断言写错（恒真断言）按 2 分处理。
- 纯文档/配置改动可豁免，验证维度记 3 分并在卡中注明"无运行时行为"。

## 3. 严重度定义

| 级别 | 含义 | 对星级的影响 |
| --- | --- | --- |
| **P0** | 阻断：无法运行、数据损坏、安全高危 | 0-1 星，必须重做 |
| **P1** | 严重：核心功能缺失/主流程错误 | ≤2 星，关键部分重做 |
| **P2** | 应修：主要边界、错误处理、明显规范问题 | ≤3 星，小修后可用 |
| **P3** | 建议：命名、注释、少量重复、可选优化 | 不影响 4-5 星 |

同一问题只定一个级别。既没处理异常又吞了异常，算一个 P2，不叠加。

## 4. 扣分参考（辅助校准，不叠加）

| 现象 | 维度 | 建议扣分 |
| --- | --- | --- |
| 缺 1 个次要验收点 | 需求 | -0.5 ~ -1 |
| 无输入校验 | 正确 | -0.5 |
| 吞异常 / 只 `print` 不抛 | 正确 | -0.5 |
| 失败后不清理临时资源 | 正确 | -1 |
| 无幂等/重试放大 | 正确 | -1 ~ -1.5 |
| 硬编码路径/配置 | 可维护 | -0.5 |
| 超长函数（>100 行） | 可维护 | -0.5 |
| 重复代码 ≥3 处 | 可维护 | -0.5 ~ -1 |
| 新增无关改动 | 可维护 | -0.5 |
| 日志含令牌/手机号 | 安全 | -0.5 |
| 无测试且无运行证据 | 验证 | -1 ~ -2 |

扣分只用于校准，**最终以锚点描述为准**，不要为了凑分做加减法。

## 5. 常见误判

1. **"能跑就是 4 星"**：能跑只说明 happy path 通，通常 3 星。
2. **"代码长=考虑周全"**：长度不加分，改动最小才加分。
3. **"解释得很清楚"**：解释不计入代码质量。
4. **"用了新框架/新写法"**：与项目一致性优先，炫技扣可维护分。
5. **"上一轮 2 星，这轮改成 3 星算进步"**：星级只看本轮绝对值，进步写在评语里。
6. **"测试通过就给 5 星"**：还要看测试是否真断言、是否覆盖异常。
7. **"是 AI 生成的所以宽容"**：评分对象是代码，不是作者。
8. **五维全 4 却给 5 星**：加权 4.0，按映射只能是 4 星。
9. **把风格偏好当缺陷**：以项目内同类代码为准，不以个人口味为准。
10. **漏看 diff 之外的影响**：改了公共函数签名，必须检查调用方，否则按"弄坏已有功能"算 G3。

## 6. 特殊场景

| 场景 | 处理 |
| --- | --- |
| 只给了片段，看不到全貌 | 只评片段内可判定项；全局性维度（集成、回归）标 `未验证`，不扣分也不给满分 |
| 纯重构，无新功能 | 需求维度改评"行为等价性"：对外行为是否完全不变 |
| 纯配置/文档 | 验证维度记 3 分；重点看正确性与副作用（配置错会导致故障） |
| 探索性原型（用户明说） | 可用宽松档：只判 G0/G1，星级上限放宽到 4，5 星仍需验证 |
| 多文件大改动 | 按"最差文件"定 Gate，按加权平均定维度分 |
| 用户要求"严格模式" | 5 星需附测试；4 星需有运行证据；任何 P2 直接压到 3 星 |
